# 拾光 · 手机故事

作者设计端和玩家手机端已拆分。无需 Anaconda。先在浏览器设计内容，再发布玩家版本。

## 现在从哪里开始

打开入口：https://zhusichen520.github.io/zhusichen520/ （需仓库启用 GitHub Pages）。

1. 选择「作者设计端」。先修改手机主人、壁纸和一个联系人。
2. 在「聊天」填写角色人设、风格、剧情边界，再连续添加开场消息。
3. 添加备忘录、照片或朋友圈，为聊天消息配置查看内容后的触发条件。
4. 用「游玩模式」测试，下载「备份」保留完整素材。
5. 静态模式可发布并下载独立玩家 HTML，玩家不能从它进入编辑草稿。

旧版本本机草稿会保留，不会因改版清空。内容不会自动从一台设备同步到另一台。

## 在线服务器部署

GitHub Pages 只能提供设计器与离线导出，不支持作者认证、数据库或 AI。在线版使用同一仓库的 server.py，Python 标准库，无第三方运行依赖。

[使用 Render 部署](https://render.com/deploy?repo=https://github.com/zhusichen520/zhusichen520)

render.yaml 使用付费 starter 服务和持久化磁盘，不是免费托管；部署前确认服务商显示的价格。部署时设置：

- AUTHOR_PASSWORD：自行设置的强作者密码，只填服务商安全设置，不要提交仓库。
- MODEL_API_KEY：可选，模型提供商 API 密钥；无密钥时人设可编辑、固定剧情可游玩，AI 明确不可用。
- MODEL_NAME：默认 gpt-4.1-mini。
- MODEL_BASE_URL：默认 https://api.openai.com/v1，可用兼容 Chat Completions 的 HTTPS 服务。
- STORY_DB：持久化磁盘内数据库路径，蓝图已配置 /var/data/story.db。
- COOKIE_SECURE：在线 HTTPS 使用 1；仅本地测试可设 0。

MODEL_API_KEY 可在部署后再填，不要把它发在聊天中。AI 请求产生模型费用；内置每 IP 每分钟 10 次、服务全局每分钟 60 次限制，不等于账单上限，公开运营前应在服务商设置预算。无用户账号，玩家按会话独立游玩；AI 历史暂不持久化。服务采用单实例，扩容前需改共享存储和会话。

部署后访问新域名的 /studio.html，点击「作者登录 / 云端」，登录后手动「云端保存」；发布时先保存草稿，再创建独立发布快照并给出 /play.html 玩家链接。草稿修改不会自动改变发布版。作者登录有效期 12 小时，服务器重启后需重新登录。自动保存仅指本机，云端保存为手动操作。

## AI 和权限范围

玩家端只读取发布内容，不能读云端草稿、写草稿或发布。角色人设不返回公开故事 API，模型密钥仅在服务器。玩家会话互不共享，但未提供账号系统、玩家云端存档或付费会员。

AI 可在模拟聊天内扮演角色，不会操作真实微信或真实手机。人设与边界属于模型提示，不能保证模型完全遵守；重要秘密和关键解锁用固定消息与内容触发。不要向模型发送敏感信息。此版本不是具有工具执行能力的 agent。

manifest 提供添加桌面和独立窗口元数据，支持情况由浏览器决定。尚未提供离线服务缓存、推送通知或应用商店安装包，不能保证所有浏览器显示安装提示。

## 开发与验证

```sh
python3 server.py
# 本地作者登录需先在本机安全配置 AUTHOR_PASSWORD 和 COOKIE_SECURE=0
node --check app.js
python3 tests/server_test.py
# 浏览器测试依赖测试环境已有的 Playwright / Chromium；另启动静态服务器于 3000
node --test tests/studio.test.cjs
```

上传单张上限 3 MB；本机 localStorage 容量有限，及时备份。清除浏览器数据会清除本机草稿，服务器磁盘丢失也会丢失云端数据，发布不替代备份。
